Executive Summary

The FDE OS delivery method structures a solo Forward Deployed Engineer's work into five sequential phases — Qualification, Assessment, Context, Engineering and Scale — each with its own objective, reference duration, deliverables and Go/No-Go gate. The framework is agnostic to client size and sector: what changes between a small business and an enterprise account is the depth and formality of each phase, never the sequence or the security gates.

From version 0.2.0 onwards, the methodology stopped being reference documentation alone and became something executed by a team of 9 specialist AI agents, each responsible for one phase or discipline, coordinated by an orchestrator agent and supported by 7 reusable skills and an operational harness with a per-engagement folder convention.

Common Antipatterns

  • Big bang without a PoC — skipping Phase 1 and going straight to complex architecture without proving value against real data.
  • Agent without output guardrails — allowing write actions in production before the Autonomous/Approval/Blocked matrix exists.
  • Too many agents — a multi-agent topology for a process a single prompt would solve.
  • RAG without a refresh strategy — vectorising once and never reindexing; the knowledge base drifts from reality within weeks.
  • Retainer without a value report — running Phase 4 without measurable monthly ROI, the leading cause of churn.

Effort Estimation & Capacity

Every fixed fee derives from a WBS + PERT estimate — never from guesswork. The fde-capacity-planner agent decomposes the phase into granular tasks, estimates three points per task and compares the total against the solo FDE's productive capacity.

Governance & Security

Mandatory from Phase 2 onwards, and a veto gate before any move to production in Phase 3, owned by fde-guardrails.

Action Autonomy Matrix

ClassDefinitionExampleApproval required
AutonomousReversible, low impact, no sensitive dataSummarise a document, classify a ticketNone (logging only)
Prior ApprovalIrreversible or medium-to-high impactSend an email, create a CRM recordA human confirms first (HITL)
BlockedFinancial action, data deletion, critical configurationTransfer, hard delete, permission changeNever automated

Non-negotiable principles

  • Inherited permission — the agent never holds broader access than the FDE in that system; no separate service account.
  • Environment-sensitive autonomy — the same action can be more permissive in sandbox or PoC and more restricted in production; promotion never inherits the sandbox's permissiveness.
  • A complete audit trail — timestamp, actor, input, tools called, output and guardrail decision, not editable by the agent itself.
  • Data-protection review before ingestion — PII masking at the input, never only at the output.
